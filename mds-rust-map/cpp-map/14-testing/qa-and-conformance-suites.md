## 1. Purpose and responsibilities

This page inventories the tests in the tree that exercise the MDS, and the external conformance suites commonly run against CephFS. For each test file, binary, suite or script it records:

- **(a) contract**: the MDS-visible behaviour it checks, linked to the map page that describes that behaviour;
- **(b) channels**: how it drives and observes the MDS. This decides whether it observes the MDS only through interfaces that unmodified peers (monitors, OSDs, managers, kernel and userspace clients, tools) also use, or whether it depends on internals of the C++ implementation;
- **(c) how it runs**: teuthology suite and facet, `vstart_runner.py`, ctest, a gtest binary or a standalone script.

Section 7 holds the inventory. Section 8.4 turns the statements that the other map pages mark as unverified, inferred or established by code reading into a backlog of runtime checks.

Verdicts used in section 7:

- **runs**: P and D only.
- **needs T/C/O/L: ...**: runs only if the MDS under test reproduces the named surface (command and JSON key names, counter names, the effect of an option, or message text).
- **no (F)** or **no (U)**: depends on C++ on-disk formats and tools, or on a released C++ MDS.

A test that only *sets* an option through the monitor, without asserting its effect, is not tagged O. The monitor accepts any option in its own schema, so those settings reach whatever MDS is under test (`qa/tasks/ceph.py:414-434`).

## 3. How it works

### 3.1 Teuthology suites (`qa/suites/fs`)

* **Facet trees.** A sub-suite is a tree of YAML facets. A file named `%` makes its directory the convolution (cartesian product) of its subdirectories, `+` concatenates all files of a directory, and `$` picks one at random (`doc/dev/developer_guide/testing_integration_tests/tests-integration-testing-teuthology-intro.rst:317-320`). One job is one combination.
* **Shared facets.** Most sub-suites link the shared facets in `qa/cephfs/`:
  * `begin/` installs packages, including `python3-cephfs`, `cephfs-shell`, `cephfs-top` and `cephfs-mirror` (`qa/cephfs/begin/0-install.yaml`), and starts the cluster with the `ceph` task (`create_rbd_pool: false`, `qa/cephfs/begin/1-ceph.yaml`).
  * `conf/mds.yaml` sets, through `cluster-conf`, `debug mds: 20`, `mds debug frag: true`, `mds debug scatterstat: true`, `mds op complaint time: 180` and `mds verify scatter: true` (`qa/cephfs/conf/mds.yaml:1-14`).
  * `mount/` is either `fuse.yaml` (the `ceph-fuse` task) or `kclient/` (the `kclient` task). The kclient facet chooses mount syntax `v1` or `v2`, and the distro kernel (`k-stock.yaml`) or the `testing` branch kernel (`k-testing.yaml`).
  * `clusters/` gives the role layout, including the number of `mds.*` daemons.
  * `overrides/` holds thresholds such as `frag.yaml`: `mds bal fragment size max 10000`, `merge size 5`, `split bits 3`, `split size 100` (`qa/cephfs/overrides/frag.yaml:1-8`).
* **Cephadm-deployed sub-suites.** `fs/workload`, `fs/cephadm`, `fs/nfs` and two of the five `fs/upgrade` sub-suites (`mds_upgrade_sequence`, `upgrade_fuse`) deploy daemons with cephadm from a container image instead (`qa/suites/fs/workload/begin/1-cephadm.yaml`, `qa/suites/fs/nfs/cluster/1-node.yaml`).
* **Option application.** The `ceph` task applies every `cluster-conf` key with `ceph config set <section> <key> <value>` (`qa/tasks/ceph.py:414-434`). `conf` keys go into `ceph.conf`.
* **Test drivers.**
  * `cephfs_test_runner` loads the listed modules, or discovers all of `qa/tasks/cephfs`. It counts a skipped test as a failure unless `fail_on_skip: false`, and stops at the first failure unless `failfast: false` (`qa/tasks/cephfs_test_runner.py:86-224`).
  * `workunit` clones the qa tree at the job's ref and runs `make` when `qa/workunits` has a `Makefile`. That `Makefile` builds `direct_io` and `fs` (`qa/workunits/Makefile:1-4`). It then executes every executable file under each named path (`find -executable -type f`) from a scratch directory inside the client mount, with `CEPH_ARGS`, `CEPH_ID`, `CEPH_MNT`, `CEPH_ROOT` and `TESTDIR` in the environment and a `timeout` (default `3h`) (`qa/tasks/workunit.py:159`, `425-450`, `512-537`). A directory spec such as `fs/misc` therefore runs every executable in it, including the Python scripts.
  * `check-counter` runs when its enclosing tasks finish. Overrides are merged inside `end()` (`qa/tasks/check_counter.py:52-54`), so a `check-counter` override takes effect only in jobs that also list a `check-counter` task. For daemon type `mds` it sends `ceph tell mds.<gid> perf dump --format=json-pretty` to daemons in `up:active` only, walks dotted names such as `mds.dir_split`, and fails if a counter never reached `min` (default 1) on any daemon (`qa/tasks/check_counter.py:89-152`). `dry_run: true` only logs.
  * Stressors:
    * `mds_thrash` stops and restarts MDS daemons and changes `max_mds` (`qa/tasks/mds_thrash.py:19`, `146-177`).
    * `mon_thrash` and `thrashosds`.
    * `fwd_scrub` loops `scrub start / force,recursive` and fails on any `damage ls` entry (`qa/tasks/fwd_scrub.py:55-83`).
    * `quiescer` sends `quiesce db` to the leader and `ops --flags=locks` to every rank (`qa/tasks/quiescer.py:137-215`).
    * `quarantine_thrasher` toggles `ceph fs subvolume quarantine` through mgr/volumes (`qa/tasks/quarantine_thrasher.py:27`, `140-170`).
  * Helper tasks: `fs.ready`, `fs.clients_evicted` (asok `session ls`, `qa/tasks/fs.py:114-167`), `fs.post_upgrade_checks`, `mds_pre_upgrade`, `exec`, `background_exec`.

### 3.2 Per-test lifecycle of `CephFSTestCase`

`CephTestCase.setUp` writes "Starting test" to the cluster log and skips memstore-only tests on other object stores. Its `tearDown` runs `ceph config reset <conf_epoch>` (`qa/tasks/ceph_test_case.py:152-173`). `CephFSTestCase.setUp` (`qa/tasks/cephfs/cephfs_test_case.py:121-207`) then:

1. Skips when fewer MDS daemons or mounts exist than `MDSS_REQUIRED`/`CLIENTS_REQUIRED` (126-134), or when `REQUIRE_ONE_CLIENT_REMOTE` is set and the first client shares a host with an MDS (136-138).
2. Clears iptables rules, unmounts every client, deletes every file system and restarts every MDS daemon "to reset any run-time configs" (144-155).
3. Runs `osd blocklist clear` (with fallbacks for old releases) and deletes `client.*` auth entities that are not mounts, `admin` or `mirror*` (100-119, 160-168).
4. Creates a fresh file system `cephfs` (171) and resets mount caps to `mon 'allow r' osd 'allow rw tag cephfs data=<fs>' mds 'allow'` (174-184). The loop `break`s after the first successful `auth caps`, so in practice only the first mount's client is reset; a later client is touched only if every earlier `auth caps` failed and was replaced by `auth add` (179-184). It then waits for healthy daemons (187) and mounts `CLIENTS_REQUIRED` clients (190-191).
5. Optionally creates `backup_fs` after `fs flag set enable_multiple` (193-199), and reads every `LOAD_SETTINGS` option through asok `config get` on the first MDS (202-205).

`tearDown` clears firewall rules, tears down mounts, deletes all file systems, restores mount details and removes the `set_conf` entries (209-223).

### 3.3 Running without teuthology: `vstart_runner.py`

* **Invocation and cluster creation.** `python qa/tasks/vstart_runner.py [--create] [--kclient] tasks.cephfs.test_x[.Class[.test]]` runs `CephFSTestCase` modules against a local cluster (`qa/tasks/vstart_runner.py:1-50`). With `--create` it runs `vstart.sh -n --nolockdep` with `FS=0`, `MDS=<max MDSS_REQUIRED of the selected tests>`, `OSD=4` and `MGR=max(MGRS_REQUIRED, 1)`; it adds `--memstore` if a selected test requires it and `-d` in verbose mode, the default (`scan_tests`, 1117-1135; 1440-1465).
* **Binaries and mounts.** It refuses to start if `ceph-dencoder` or `rados` is missing from the build unless `--ignore-missing-binaries` is given (1410-1417). Before starting, it kills any process of the user whose `ps` line contains `ceph-fuse` or `ceph-mds` (1428-1438). Mounts are ceph-fuse unless `--kclient` is given (1375, 1504-1509).
* **Daemon control** is by process name:
  * An MDS is the process whose `ps ww` line contains `ceph-mds -i <id>` (`LocalDaemon._get_pid`, 539-556).
  * Stop sends `SIGTERM` and waits (566-595). Restart runs `<bin>/ceph-mds -i <id> -f` (597-603).
  * Admin-socket commands run as `ceph daemon mds.<id> <cmd>` (851-858).
  * `set_ceph_conf` edits `./ceph.conf` below a `#LOCAL_TEST` banner (885-929).
* **Settings it adds itself.** It sets `mds log max segments = 10` and `mds root ino uid/gid` to the invoking user (1540-1548).
* **The `vstart.sh` side.** `vstart.sh -d` loads `[mds] debug_mds = 20`, `mds_debug_scatterstat`, `mds_verify_scatter`, `mds_debug_frag`, `mds_debug_auth_pins` and `mds_debug_subtrees = true` into the monitor config store (`src/vstart.sh:1808-1840`). It creates each MDS key with `mon 'allow profile mds' osd 'allow rw tag cephfs *=*' mds 'allow' mgr 'allow profile mds'` (`src/vstart.sh:1540`) and starts `ceph-mds -i <name>` (`src/vstart.sh:1549`).
* **Test filtering.** `exec_test` drops `@for_teuthology` tests, and `@needs_trimming` tests when not running as root, from the suite it loaded with the decorating loader (1562-1593). It then reloads the modules with a plain `TestLoader` and runs that new suite (1594-1595), so the dropped tests run anyway (section 8.1).

### 4.2 Invariants the harness establishes before each test

* **Fresh state per test.** Every test starts on a newly created file system named `cephfs`, with freshly restarted MDS daemons, an empty OSD blocklist and, for the first mount's client, caps reset to `mds 'allow'` (section 3.2; other clients keep the caps an earlier test left). Persistent MDS state from earlier tests is therefore not inherited. The monitor config store is not recreated: `CephTestCase.tearDown` rolls it back with `config reset` to the epoch that the `ceph` or `cephadm` task saved when the cluster came up (`ceph_test_case.py:169-173`, `qa/tasks/ceph.py:450-452`, `qa/tasks/cephadm.py:1936-1938`, `qa/tasks/ceph_manager.py:1654-1658`).
* **Intentional crashes.** Tests that crash an MDS on purpose (kill points, injected aborts) delete the resulting core file so that teuthology's coredump check does not fail the job. The helper is `CephFSTestCase.delete_mds_coredump` (`cephfs_test_case.py:303-336`); callers include `test_failover.py:1009`, `test_fragment.py:103`, `test_exports.py:676`, `:756`, `test_damage.py:617`, `:653`, `test_misc.py:806` and `test_snapshots.py:90`.
* **Cluster layouts.**
  * `fs/functional` uses `1a3s-mds-4c-client`: MDS daemons `a`-`d` and clients 0-3 on 2 nodes (`qa/cephfs/clusters/1a3s-mds-4c-client.yaml`).
  * `fs/workload` uses 12 MDS daemons on 3 nodes (`1a11s-mds-1c-client-3node`).
  * `fs/thrash/workloads` and `fs/verify` use 6 (`1a5s-mds-1c-client`).
  * `fs/full` uses 4 MDS daemons and 1 OSD on one node (`1-node-4-mds-1-osd`).
  * `fs/multiclient` uses 2 MDS daemons and 3 clients (`1-mds-3-client`).

## 6. Concurrency and mds_lock

These are facts about how the suites exercise concurrency. The MDS-side serialization itself is described in [mds_lock-analysis](../00-architecture/mds_lock-analysis.md) and [process-and-threading](../00-architecture/process-and-threading.md).

* **Multi-client and mixed-client concurrency:**
  * `fs/multiclient` runs ior and mdtest over MPI (`qa/suites/fs/multiclient/tasks/{ior-shared-file,mdtest}.yaml`).
  * `fs/mixed-clients` runs different workloads in parallel from a kernel and a ceph-fuse client on one file system.
  * Multi-client tests: 18 of the 50 modules have a class with `CLIENTS_REQUIRED` of 2 or more (for example `test_client_recovery.py`, `test_quota.py`, `test_fscrypt.py` `TestFSCryptRMW`; `TestSessionClientEvict` needs 3, `test_misc.py:600`), and `src/test/libcephfs/multiclient.cc` uses two mounts in one process.
* **Daemon and message disturbance:** `mds_thrash`, `mon_thrash`, `thrashosds`, `msgr-failures/osd-mds-delay.yaml` (`ms inject socket failures: 2500`, `ms inject delay type: client mds osd` on the MDS), `fwd_scrub`, `quiescer`, `quarantine_thrasher`, and the `4-flush` loop (`ceph tell mds.cephfs:0 flush journal` every 13 s, `qa/suites/fs/workload/tasks/4-flush/yes.yaml`).
* **Lock validators apply only to the C++ build:** `lockdep: true` (`fs/verify/validater/lockdep.yaml`, `fs/functional/tasks/admin.yaml`, `fs/bugs/multifs_mdsauthcaps` and `fs/bugs/snapshot_visibility_on_upgrade`; not `fs/bugs/client_trim_caps`), and valgrind memcheck on the MDS with `mds valgrind exit: true` (`qa/suites/fs/verify/validater/valgrind.yaml:16-24`).
* **Admin commands issued while client requests are blocked inside the MDS:**
  * `ops --flags=locks` during quiesce (`qa/tasks/quiescer.py:172-215`).
  * `op kill` of a `lock path` op that holds `snap:r` while a setxattr waits (`test_subvolume.py:258-262`).
  * `session ls` while clients are stale (`test_client_recovery.py`).

  These rely on the admin socket staying responsive while requests wait for locks. The C++ handlers of `session ls`, `client ls` and `session evict` take `mds_lock` ([mgr-tools-and-orchestration](../01-cluster-integration/mgr-tools-and-orchestration.md) §6.2).
* **Concurrency races driven by options:** `mds_inject_migrator_session_race` (`test_exports.py:33-42`), `mds_sleep_rank_change` (`test_failover.py:567`; `fs/thrash/workloads/overrides/races.yaml`), and `mds_cache_quiesce_delay` (`test_quiesce.py:569`, `1004`).
* **Concurrency inside a single test process.** `filelock_deadlock.py` forks three processes that each hold one POSIX lock and wait for the next, and expects exactly one `EDEADLK` (`qa/workunits/fs/misc/filelock_deadlock.py:15-67`). `filelock_unlock_upgrade.py` blocks an `flock` upgrade in a thread and then unlocks from the same owner (`qa/workunits/fs/misc/filelock_unlock_upgrade.py:48-90`).

## 8. Edge cases, failure handling and gotchas

### 8.1 Harness gotchas

* **vstart_runner filtering is discarded.** `exec_test` removes `@for_teuthology` and `@needs_trimming` tests from the suite it built with the decorating loader (`qa/tasks/vstart_runner.py:1562-1593`). It then reloads the modules with a plain `TestLoader` and launches that suite (`:1594-1595`), so the removed tests run anyway. They still find `ctx`, `mounts` and the other harness objects because `DecoratingLoader` sets them as class attributes (`qa/tasks/cephfs_test_runner.py:23-29`).
* **vstart_runner finds daemons by process name.** It kills stray `ceph-mds` processes before starting (`qa/tasks/vstart_runner.py:1428-1438`), and recognises an MDS as the process whose `ps` line contains `ceph-mds -i <id>` (`:539-556`).
* **A broken facet runs nothing.** In `qa/suites/fs/functional/tasks/mds_creation_retry.yaml` the line `-mds_creation_failure:` has no space after the dash. PyYAML parses the file as `{'tasks': None, '-mds_creation_failure': [{'workunit': ...}]}`, so neither the `mds_creation_failure` task (`qa/tasks/mds_creation_failure.py:43`, `mds_kill_create_at=1`) nor its workunit is in the job's task list. Teuthology's handling of the unknown top-level key is unverified. The task would fail even if it ran: it uses the undefined names `self` and `mds` (`qa/tasks/mds_creation_failure.py:1`, `34-36`, `43`, `59`).
* **Task lists nested under `overrides`.** In `qa/suites/crimson-rados/cephfs/tasks/test/`, `cfuse_workunit_suites_{blogbench,fsstress,pjd}.yaml` and `libcephfs_interface_tests.yaml` indent `tasks:` under `overrides:`, so PyYAML yields no top-level `tasks` key; only `cfuse_workunit_suites_iozone.yaml` has one. Those jobs therefore carry only the tasks of `0-crimson_install.yaml` (`install`, `pexec`) and `deploy/ceph.yaml` (`ceph`), and no CephFS workunit, unless teuthology does something with `overrides.tasks` (unverified).
* **A duplicate YAML key drops a counter check.** `qa/suites/fs/workload/tasks/6-workunit/fs/norstats.yaml` defines `overrides` twice. PyYAML keeps the second mapping, which drops the `check-counter` override. `qa/suites/fs/functional/tasks/snap_schedule_snapdir.yaml` has the same defect: its second `overrides` (lines 19-25) replaces the first, dropping the mgr debug levels and the full-pool `log-ignorelist` of lines 1-17. That teuthology loads facets with PyYAML semantics is assumed, not verified.
* **Inert `check-counter` overrides.** `qa/tasks/check_counter.py:52-54` merges overrides only inside a running `check-counter` task. `fs/verify` and `fs/thrash/workloads` list no such task, so their `ranks/{3,5}.yaml` counter checks and `kernel_untar.yaml`'s `mds.dir_split` check never run. The same applies to `fs/functional/tasks/snapshots.yaml`'s `dry_run`.
* **`dry_run` disables every counter check of a job.** `dry_run` is one flag for the whole task (`qa/tasks/check_counter.py:57`, `146`). In `fs/workload`, the `6-workunit` facets `direct_io.yaml`, `fs/test_o_trunc.yaml` and `suites/{fsync-tester,iogen,iozone}.yaml` set `check-counter: dry_run: true`, so in those jobs the `ranks/multi` (`exported`, `imported`, `dir_update`) and `3-snaps` counter checks are only logged.
* **Tests that no suite runs:**
  * `test_mantle.py` (6 tests).
  * `test_volumes.TestRenameCmd` (5 tests, `test_volumes.py:997-1118`).
  * `qa/workunits/fs/damage/*.sh`, `multiclient_sync_read_eof.py` and `snap-hierarchy.sh`.
  * fstests `tests/ceph` (`run_ceph_tests`, `xfstests_dev.py:409-410`).
  * `src/test/libcephfs/quota.cc` (not built).
* **fstests exclusions are mostly not applied.** `XFSTestsDev.write_ceph_exclude` writes `ceph/001 generic/003 generic/075 generic/538 generic/531` to `ceph.exclude` (`xfstests_dev.py:328-336`). `run_test` never passes `-E`, and fstests reads an external exclude file only with `-E` (`fstests/check:436-441`), so `tests_from_xfstests_dev` runs those tests too. Only `TestFSCryptXFS.test_fscrypt_dummy_encryption_with_quick_group` passes `-E ./ceph.exclude` (`test_fscrypt.py:591`). Even there, `check` reads the file line by line and expunges a test only if a line starts with its id (`fstests/check:436-441`, `729-742`); `ceph.exclude` holds all five ids on one line, so only `ceph/001` is excluded.
* **Not-run fstests count as passes.** `check` adds a test to `try` before running it, so a test that reports "not run" still ends with "Passed all 1 tests" (`fstests/check:1063-1065`, `:661`). `run_test` counts only non-zero exits and "Passed all 0 tests" as failures (`xfstests_dev.py:366-378`).
* **The unpinned fstests clone breaks a fixed count.** `TestFSCryptXFS.test_fscrypt_encrypt` asserts `Passed all 26 tests` for `-g encrypt` (`test_fscrypt.py:581`). At fstests `3e1ee800e52a` the `encrypt` group has 29 members in `tests/generic`, and `tests/ceph` has none. The clone is unpinned (`xfstests_dev.py:141-142`), so the assertion depends on the day's fstests HEAD; the test was not run here.
* **Skips count as failures by default.** `cephfs_test_runner` turns skips into failures unless the facet sets `fail_on_skip: false` (`qa/tasks/cephfs_test_runner.py:164`, `199-204`). Kernel-only and fuse-only modules rely on that flag: `test_quarantine.py` skips on kclient and `test_quarantine_kclient.py` on fuse (`qa/suites/fs/functional/tasks/quarantine.yaml:1-17`).
* **Class-level asok dependencies.** `LOAD_SETTINGS` makes every test of a class depend on MDS asok `config get` (section 4.1). In the same way, `FullnessTestCase.setUp` reads `osdmap_epoch_barrier` from asok `status` for every `test_full` test (`test_full.py:27-33`).
* **The scan counts are approximate.** The P-only counts in 7.1 come from a static scan that follows `self.<helper>()` calls inside one module, and calls through `super()` are not followed. They were corrected by hand where this was found (`test_full`, `LOAD_SETTINGS` classes, `test_mirroring`, `test_snapshots.TestMonSnapsAndFsPools`, `test_misc.test_fs_new`; on review, `test_admin`'s 14 health-warning tests and the two non-MDS `TestConfigCommands` tests, and `test_volumes.test_subvolume_pin_random`).

### 8.2 Tests that pass through P but encode C++-specific values

* **Reserved inode numbers.** `LibCephFS.LookupInoMDSDir` and `LookupMdsPrivateInos` (`src/test/libcephfs/test.cc:3238-3251`, `4213-4243`) fix which inode numbers below `MDS_INO_SYSTEM_BASE` must resolve: 1 and 3 must, 0, 2 and 5-0xff must not, and 4 may. libcephfs answers `[0x100, 0x1000)` itself (`src/client/Client.cc:192-198`).
* **Compat-set feature ids.** `test_admin.TestCompatCommands` needs the joining MDS to advertise incompat feature id 1 and to be refused when the fs requires id 63 (`test_admin.py:1389-1417`) -> [fsmap-and-mdsmap](../01-cluster-integration/fsmap-and-mdsmap.md).
* **Snapshot naming.** `qa/workunits/fs/snaps/snaptest-snap-rename.sh:15-25` and `snaptest-upchildrealms.sh` depend on the `_<name>_<ino>` naming of parent snapshots, and `snaptest-name-limits.sh:19-23` requires a 241-character snapshot name to be refused -> [snapshots](../10-snapshots-quotas-subvolumes/snapshots.md).
* **Quota value ranges.** `fs/quota/quota.sh` pins quota value ranges, for example `8388607Ti` accepted and `8388608Ti` refused.
* **Xattr size limit.** fstests assumes a 64 KiB total xattr budget for CephFS (`fstests/tests/generic/020:154-169`).
* **Health detail text.** `test_failover.TestFailoverBeaconHealth` parses the `MDS_ESTIMATED_REPLAY_TIME` detail text with a regex (`test_failover.py:380-385`). The health code reaches the monitor through the beacon, but the text format is the C++ MDS's.

### 8.3 External-suite gotchas

* **Pinned and unpinned external code.** The qa `pjd.sh` runs a 2009 snapshot whose `tests/conf` claims ext3, so tests that branch on `$fs` use ext3 expectations (`pjd-fstest-20090130-RC/tests/conf:8`). `fsstress.sh` uses LTP's fsstress from 2009. `fsx.sh` builds fsx from xfstests-dev at the pinned commit `0e5c12dfd008`, committed 2024-04-11 and pinned in this tree on 2024-05-06 as "the latest master head" (`qa/workunits/suites/fsx.sh:7-8`; the commit date is from the xfstests-dev history, the pin date from this repository's commit `740025da227`). `XFSTestsDev` uses whatever xfstests-dev HEAD is current.
* **What fstests does not check for CephFS.** It cannot re-create a CephFS scratch filesystem and runs no consistency check for ceph (section 3.5). Tests that need a fresh filesystem therefore run on leftover state, and no fsck-style check catches metadata corruption.
* **LTP and pynfs reach the MDS only indirectly.** LTP's device-formatting tests and pynfs's server tests do not talk to the MDS directly. LTP needs `TMPDIR` on the mount. pynfs reaches the MDS only through Ganesha and libcephfs, so its results mix Ganesha and MDS behaviour.
