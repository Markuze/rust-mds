### 3.1 Transport and message instance rules

References: C++ `src/include/msgr.h::{ceph_msg_connect,ceph_msg_connect_reply,ceph_msg_header,ceph_msg_footer}`, `src/msg/async/ProtocolV1.cc::{handle_connect_reply_2,handle_ack_seq,client_ready,handle_message_footer,write_message,requeue_sent,discard_requeued_up_to,session_reset}`, and `src/msg/Message.{h,cc}` CRC routines. Local main is not proof of an installed package's emitted fields.

- Support the capture link/IP profile actually selected later. Start from observed SYN/SYN-ACK and both msgr banners. Record network namespace/interface and both TCP initial sequence numbers. A reused tuple is a new TCP stream. Handle TCP sequence wrap, split/coalesced messages, out-of-order segments, FIN/RST and identical overlap. Reject conflicting overlap, unsupported IP fragmentation/profile, snaplen truncation, unresolved holes or incomplete required frames. Count duplicate loopback observations once by packet/sequence identity, not payload timing. Preserve bounded overlap validation history; an unverifiable old overlap cannot silently pass.
- Implement the **nine-byte `ceph v027`** handshake. Client sends one 136-byte legacy address; server sends its address and the observed peer address. Then parse connect33/reply26 and bounded challenge/retry rounds. Skip authorizer lengths in memory; retain only non-secret negotiation fields. Use the accepted feature mask, host/entity type, advertised address+nonce, `global_seq` and `connect_seq`. A successful reply advances the session connect sequence as C++ specifies. Handle RESETSESSION, RETRY_SESSION, RETRY_GLOBAL, READY and SEQ distinctly; reject invalid state/tag transitions.
- A message is tag7 + header53 + front/middle/data + footer. Header is packed little-endian `<QQHHHIIIHBQHHI>`: seq, tid, type, priority, version, three lengths, data_off, source type/number, compat, reserved, CRC. `data_off` is metadata, not bytes of padding in this msgr1 frame. Footer is21 bytes with negotiated MSG_AUTH (bit23), otherwise13. Handle ACK8/u64, SEQ13 negotiation/u64, CLOSE6, KEEPALIVE9 and KEEPALIVE2/ACK14/15 with their eight-byte timestamps in their correct states.
- CRC is **CRC32C/Castagnoli**, reflected polynomial `0x82f63b78`, seed0 with Ceph's non-complemented update convention. Header CRC covers the first49 bytes. Front/middle CRCs cover their exact segments; compute data CRC incrementally while skipping unneeded payload. Respect FOOTER_COMPLETE=1, NOCRC=2 (data only) and SIGNED=4. Record explicitly when the protocol omits data CRC; never label it checked. Reject bad mandatory CRCs and aborted frames. Do not substitute `zlib.crc32`. Signature bytes are skipped; the observer does not verify secrets. Identity comes from the independent peer/stream join plus authenticated daemon binding.
- Maintain a messenger session epoch distinct from the TCP stream. MSG_AUTH can randomize the initial sequence after reset. C++ permits forward sequence gaps and discards old sequences; a gap alone is neither packet loss nor proof of a missing message. TCP byte coverage supplies that proof. SEQ/ACK and reset history establish reconnect continuity. Record an old-seq transport replay separately. A new Ceph application resend requires a new verified message instance with the same request/flush tid and peer-send evidence. It is never inferred from TCP retransmission, a reused seq after reset, or a new application call. Retain `(TCP stream, direction, frame byte offset, messenger epoch, seq, tid, type)` so these cases cannot collapse.

## 4. P2: complete WireNfs41 correlation

Use standard **nested PDML** from the pinned decoder as the first input. This avoids a second general packet/RPC framework. [Wireshark v4.6.4 `packet-nfs.c`](https://github.com/wireshark/wireshark/blob/v4.6.4/epan/dissectors/packet-nfs.c) has `dissect_nfs4_{compound_call,compound_reply,request_op,response_op}`: each operation has its own opcode subtree and result status. It caps dissection at128 operations; reject a count mismatch or too-many-ops/malformed expert result. Do not treat its truncated tree as complete. `open_owner4`, `lock_owner4`, `session_id4` and `stateid` are byte fields. Require full `value` bytes and sizes, not display text, CRC16 stateid or CRC32 FH summaries. This source fact does not qualify installed output.

[RFC5662](https://www.rfc-editor.org/rfc/rfc5662) supplies XDR layouts; [RFC8881](https://www.rfc-editor.org/rfc/rfc8881) supplies v4.1 operation/session semantics. XDR numbers are big-endian, variable opaque values have u32 lengths and four-byte padding, sessionid/stateid are16 bytes. Native RPC framing must also be complete: record-marked TCP fragments, RPCv2, program100003/version4/procedure1, matching accepted reply and `minorversion=1`. Skip opaque RPC credentials/verifiers without retaining them. If installed PDML omits required bytes or boundaries, add only the missing bounded XDR field extraction to this same module from transient complete RPC bytes. Such a fallback needs fixtures/review before readiness; never fill fields from Ganesha guesses.

Implement these joins as bounded maps with explicit expiry only after durable terminal receipts:

1. **RPC → ordered operations.** Key calls by TCP connection epoch/direction/xid and request identity; match reply op indices/opcodes to the executed prefix. The first failing op stops the compound. Do not count unexecuted later ops, or the compound's top-level status as every op's status. Keep original packet/byte references through TCP/RPC reassembly and multiple RPCs per packet. Conflicting duplicate xid bodies fail; exact RPC retransmissions do not create another operation.
2. **Client → session.** EXCHANGE_ID client-owner/verifier and successful reply clientid/server-owner/server-scope → matching CREATE_SESSION clientid/sequence and successful sessionid → SEQUENCE sessionid/slotid/sequenceid. Track session destruction/recreation and connection binding; a reconnecting TCP tuple does not create a new NFS client. Require a complete observed establishment chain. Distinct mounts with one negotiated clientid are one client for N3.
3. **SEQUENCE replay.** Key logical requests by server/session/slot/sequence. Validate echoed sequence/slot/session. Associate retries across xid/TCP changes with the original operation list. Retain successful and failed/replayed result identities. Sequence misuse, a missing predecessor needed for a join, or a conflicting cached result fails. Apply the protocol's slot sequencing, not Ceph tid rules.
4. **Current and saved FH.** Start each compound with no current/saved FH. Execute successful PUTFH/PUTROOTFH/LOOKUP/LOOKUPP/OPEN/CREATE/SAVEFH/RESTOREFH/GETFH effects in order, with reply status. Name-based OPEN changes the current FH to its target; CLAIM_PREVIOUS uses the supplied existing FH. GETFH binds the full returned bytes to that exact current-FH state. An unresolved namespace transition stays unresolved until a legitimate returned/known FH binds it. Never carry a current FH from an unrelated compound, or attach the nearest later GETFH across another FH-changing op. Support READ/WRITE/COMMIT/GETATTR and relevant lock/close operations without retaining data; reject an unmodelled FH/state-changing operation affecting a required join.
5. **Owner → state.** OPEN owner is `(session-derived client identity, full opaque owner)` plus exact claim/share/open fields. RFC8881 requires the server to ignore embedded OPEN/LOCK owner clientid and the legacy OPEN/LOCK owner-sequencing fields in v4.1; retain them as decoded facts, never as the identity/replay authority. Successful OPEN stateid binds that owner and target FH. LOCK's `new_lock_owner` union either supplies open_stateid/open_seqid/lock_seqid/clientid/lock_owner, or supplies existing lock_stateid/lock_seqid. Resolve both branches. Track returned stateid generations, LOCKU and CLOSE; handle special/current-stateid semantics explicitly. Preserve full salted16-byte stateid identity and its seqid/other relationship. Record lock type, offset and length; all-ones length means through EOF. Never mix a DENIED reply's conflicting owner with the request's owner.
6. **RECLAIM_COMPLETE.** Associate `one_fs=false` with its actual client/session. It has no required file handle or open/lock owner. P4 relates this client-wide completion to prior reclaimed owners; P2 must not invent per-op owner/FH fields. Accept COMPLETE_ALREADY only with the earlier exact successful completion and matching replay identity as required by §6.3.
7. **FH → Ceph inode/key.** Reuse `nfs_handle` for the ordinary29-byte V6.5 handle: `43,flags,export:u16be,fs_len=24`, then `ino:u64le,snap:u64le,fscid:i64le`. Require export100/fscid44 and the observed head-snapshot value. Retain the salted full-handle hash, not `st_ino`. Ganesha sources are V6.5 `include/nfs_fh.h`, `support/nfs_filehandle_mgmt.c`, `FSAL/FSAL_CEPH/{internal.h,handle.c,export.c}`. Reject DS/foreign/unsupported shapes.
8. **Worker → NFS → native session.** Use worker call/FD/mount anchors, raw name hashes or saved FH/inode and exact RPC operation/owner state. Then match that FH's Ceph inode/path to the owned Ganesha libcephfs stream and authenticated daemon key/attachment. Serialize same-inode discovery if necessary to remove ambiguity; do not use timing alone. N3 deliberately permits two distinct NFS client identities to share one native SessionKey. Preserve each edge separately, including Ganesha PID/start/library instance across MDS restart.

**Offline fixtures:** nested compounds with repeated fields and different FHs; SAVEFH/RESTOREFH; OPEN+GETFH versus CLAIM_PREVIOUS; error-shortened replies; interleaved xids and slots; exact replay versus conflicting duplicate; two mounts sharing one clientid; two clients sharing one Ceph key; zero/arbitrary embedded owner clientid with valid session-derived identity; session recreation; new/existing lock-owner unions and stateid updates; full handles differing outside short hashes; one_fs=false without FH; GRACE/DENIED/NO_GRACE and COMPLETE_ALREADY without prior OK. Include malformed XML, entity declarations, oversize nodes/counts and missing raw bytes. Synthetic RPC/PDML goldens are sufficient for parser acceptance, not installed-provider acceptance.
