### 8.6 Bounded local algorithm — driver pseudocode, not implementation

The following is implementable **after** the one proposed observation is agreed and implemented. It is not a claim that the current candidate has that method.

```text
At checked engine replacement:
    create a new daemon engine-instance identity
    seen_release := engine.retry_capacity_epoch()
    retain/revalidate outstanding origins under the normal restart policy
    never transfer an old instance's epoch credit or automatically replay a stale input

For each real public engine call / matching journal callback:
    preserve the input's origin and linear permit ownership
    execute that one allowed call
    handle returning ownership/errors before any next scheduled action
    if failure()/Failed/InvalidRetryIdentity/ControlCapacity made the path terminal:
        preserve terminal input and uncertain store/job identities; schedule nothing
    otherwise materialize every effect/notice through the normal bounded funnels
    record the returned StepState
    now := engine.retry_capacity_epoch()
    if now differs from seen_release:
        seen_release := now
        retain one coalesced local capacity-pass obligation

On external RetryCapacity:
    retain exact returned input + original context/charge in external pressure wait
    release returned permit exactly once
    stamp waiter.last_attempt := (engine-instance, seen_release)
    do not create an engine-owned duplicate or an immediate retry

On a fresh allowed scheduling turn:
    serve required controls/commits and engine-reported NeedsAdmission normally
    resume owned work with step(None, fresh permit), never by replaying its input
    do not resume WaitingInput merely to discover whether it might fit
    if one-record/phase/output/admission gates permit Requests and a capacity pass is due:
        freeze a pass over at most the bounded external waiter set
        visit eligible waiters in stable order, at most once per observed epoch
        stamp its last_attempt before moving the exact input into step
        RetryCapacity -> park unchanged; keep scanning later eligible candidates
        Busy -> preserve as dependency-blocked; wait for its normal real dependency wake
        accepted -> engine owns it; retain only the origin/context record
        WaitingCommit -> stop new admitted steps until the matching callback
        fatal/returned invalid owned identity -> stop synchronously, never resubmit
    yield after the existing per-turn budget; retain the pass cursor, not a polling flag
```

One epoch can trigger at most one attempt per external waiter. A later real release grants a new pass; coalesce intervening epochs to the latest observed value. A budget yield continues the same finite pass, not a new wake. A nonfitting front waiter cannot hide a later fitting candidate. Busy dependency wake is separate from capacity credit; an unchanged Busy result cannot regenerate either obligation. A newly received Request gets its normal initial attempt under admission rules, not a fabricated old-waiter credit.

The driver must not require global Idle before a fitting eligible input can pass an engine-owned pressure waiter that reports WaitingInput. It must still accept Busy exclusions for other owned dependencies. During D5 Controls no Request is eligible. During recovery reply/output drain, fresh mutations cannot bypass retained retries. Healthy ACTIVE alone permits the already-contracted fitting watermark/independent-close bypass. No epoch advances the marker, opens ACTIVE, proves cleanup or substitutes for the required final OPEN transport handoff.

### 9.3 Caller algorithm confirmation and identity-only clarification

Retain section 8.6's algorithm and ownership registry. After each real engine call/callback, handle returned input/unused permits and `failure()`/Failed first. Materialize all normal effects/notices before another admitted step. Only then compare the instance-local epoch with the last sample and retain one coalesced external-capacity pass. Use change, not the number of increments, as credit. Stamp each external waiter once per observed epoch; preserve the finite pass cursor across budget yields. A nonfitting front waiter does not hide fitting eligible work.

Do not derive credit from Tick, a permit return, checkpoint/publication/trim, a read-only observed floor or output transport. These may be real ordinary events, but unchanged epoch gives no capacity pass. Compare the getter after an otherwise required public call; do not generate calls or a timer to look for changes. A newly constructed/restored engine gets a new local identity/baseline and cannot inherit old credits.

Identity work is a separate readiness obligation:

- Record NeedsAdmission even when the epoch is unchanged. It may now include invalid-owned-request work. Do not wait for a capacity epoch to resume that work and do not send the original Request again.
- Use the normal fresh permit when available. If it is unavailable, one `step(None, None)` probe may consume a **fresh public NeedsAdmission notification** and return an invalid owned input without a permit. This is not a WaitingInput poll. Keep at most one no-permit probe credit per new input/callback readiness notification; an unchanged NeedsAdmission returned by that probe cannot regenerate credit. Otherwise wait for the real permit/dependency event.
- WaitingInput alone supplies neither an empty-resume nor an external-capacity retry obligation. No separate identity counter, private queue test or projected-charge query is required.
- On an owned InvalidRetryIdentity return, resolve the returned key/tid/original opcode against the bounded origin registry. Preserve the original wire validation context and existing charge plus the exact returned remaining input. Return the unused permit once. Check the failure latch first so epoch exhaustion stays classified Capacity; otherwise take the existing synchronous protocol fail-closed path. Stop before outbox/job/output scheduling or any epoch pass. Never resubmit the stale Request or use another empty step to discover state.
- Apply the same terminal priority to ControlCapacity/Failed, including a returned ordinary Request on epoch exhaustion. Preserve active control cursor and uncertain store/job envelopes. Epoch changes never revive a failed engine.

Engine input ownership, daemon input charge and funnel output charge remain separate. A reply materialization can free the engine's retained context while its output remains queued/charged. That permits only the normal phase-eligible capacity attempt; it does not free the wire context early, bypass output bounds or complete D5's transport drain. OPEN.seq and R1 ownership checks still occur at the actual funnel handoff.
