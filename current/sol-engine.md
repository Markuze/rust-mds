## E2 daemon caller checklist — 2026-10-25

1. Add the unit `EngineInput::RecoveryControlsDrained` to exhaustive consumers. No new output notice, session field, owner/I/O type or persistent schema is required.
2. Every `Engine::restore` starts in Reconstruction, including fresh Ready bootstrap, empty clientless restart and load after an ACTIVE map. Reconstruct validated chunks. Complete excluded keys' fenced Closing/engine receipt/Closed chain. Pass the duplicate-free **full surviving Open-key set** to `finish_reconnect(keys)` with no commit/continuation and submitted = durable = journal committed. A first invalid/failed finish changes no phase. Never use legacy `reconnect_done` to bypass the boundaries.
3. Structural success only opens Control drain. It can return retained lifecycle/TRUNC effects and `NeedsAdmission` for bounded revoke evaluation. Process output and drive that state. It does not grant, release ordinary requests or schedule new stray purge. `Idle` can still mean an outside-engine control/job wait. Same-set finish repeats return current state with empty output, including after a later close; a different set is invalid. Chunks/reset cannot reopen the seal.
4. Run CapUpdate/CapRelease/CloseSession/Tick/LifecycleCompleted during drain. Query `pending_jobs` after cap/commit changes. A new dirty update blocked by RecoverSize without issued writer rights returns Busy with exact input/permit unchanged. Retain it and schedule eligible acknowledgments, retained truncate/probe work and completion ahead of its retry, not behind a strict FIFO head. A dirty writer revoke ACK can atomically replace probe guards; old results cannot retire the replacement. Durable duplicate flushes ACK without metadata replay. Probe failure retains the job.
5. After the **complete ordered control cut** drains or its key finishes fenced durable cleanup, send the marker once. Include controls still outside the engine; deleting/resetting a queue is not completion. Reconstruction or any pending commit/continuation returns Busy unchanged. Without a permit in Control drain, the engine owns the marker and returns NeedsAdmission. Resume `step(None, Some(permit))` in a fresh admitted turn without waiting for another packet, Tick or journal callback. Do not resubmit an owned marker. If capacity is unavailable, retain the obligation and keep readiness closed.
6. Marker execution is pure in this implementation: no WAL, notice, grant payload or follow-on transaction in that turn. It returns the same permit unused. It schedules fresh evaluation from committed state, deferred inode/SessionKey range notifications and unclaimed-stray work. Drive each NeedsAdmission turn and materialize its effects before another admitted step. A later released-marker duplicate is empty and returns the permit, unless pending commit/continuation exclusion returns Busy. Grant-only waits do not spin before release.
7. Migrate `persistence::open`, `Server::from_loaded`, `try_finish_recovery`, `pump`, `daemon::drive_phase` and their fixtures together. Track structural finish, marker ownership/execution, work/output drain and confirmed service separately. Structural finish permits requesting REJOIN while `recovered` is false. `try_finish_recovery == true` / `recovered == true` require both boundaries and required output/work drain. Ordinary requests additionally require confirmed ACTIVE and authority gates. CREATING/STARTING and clientless ACTIVE-map loads also execute both boundaries; do not invent monitor transitions. No nonempty E1 retry policy is supplied by E2.
