## Consumer migration (current package supersedes the earlier F1 API statement)

- Journal implementations must return Result<JournalSeq, JournalError> from submit. Initialize submitted/committed adapter positions to the recovered tail after checked replay; allocate tail + 1. Advance committed_seq before journal_event(Committed). Filter owner generations outside engine. A submit error after mutation is terminal, including Capacity. EngineConfig.max_record_bytes defaults to 16 MiB; reserve a slot with a compatible RecordPermit bound and also check actual encoded bytes in the adapter.
- Store codecs must version CompletedRequest/ClientFlush with session_incarnation; encode closed_sessions as SessionKey records; add RecordKind::LifecycleComplete, lifecycle_intents and completed_jobs; preserve InodeCore.stray_auth_path, stable_subvolume_id and old_layouts. InodeCore.old_pools remains. EngineCheckpoint, CheckpointInode and CheckpointSession have the normative contract fields, including cleanup_receipts. New types are in src/durability.rs and reexported at engine root. No log-history checkpoint is used.
- Daemon production calls step(input, permit), step(None, permit), and journal_event(event), not the direct client-id helpers. Process effects before resuming. Return unused_permit immediately. Busy returns input and permit untouched. Reserve capacity for cap acknowledgments, unlocks, fenced close and job completion progress. Do not poll WaitingCommit/WaitingInput. Closed rank publication requires SessionCleanupCommitted or session_cleanup_seq(key), never absence of caps.
- Effect gains Lifecycle(LifecycleIntent); update exhaustive matches. Schedule by job id with one execution in flight per owner/id through completion commit. Query pending_jobs after cap-state changes and reconnect; worker errors retain jobs. Feed successful completion through EngineInput::LifecycleCompleted. Recovery recalls other writers; their dirty acks can replace the old probe intent atomically. The daemon drains destructive I/O and filters stale-owner results. Unset purge layouts represent metadata-only data work and must not generate OSD operations against pool -1.
- Loading uses restore and replay_record, then idempotent install_session_key for joined Open/Closing rank records. Closed records must agree with cleanup receipts and must never reinstall. Reconnect adapters are reconnect_chunk, reset_reconnect, reconnect_cap_context and finish_reconnect. Chunks return authoritative realm traces for daemon SNAP UPDATE encoding; engine has no wire feature/auth/address types. The daemon still owns gather byte/count limits, required features, clientreplay reply validation and monitor state transitions.
