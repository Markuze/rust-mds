## Public API and integration notes

- All new facade and contract types are re-exported from store's crate root.
- Native: RadosBackend::new(Objecter, metadata_pool). Configure a finite Objecter operation timeout in the daemon.
- StableStore::new(backend, identity, Limits), inspect_control(), open(expected, new_owner, writer, predecessor), append(owner, expected_tail, batch_id, bodies), reconcile_pending(), load(opened), write_checkpoint(owner, generation, state), publish_checkpoint(owner, expected_generation, descriptor), trim(owner, descriptor, contiguous_sequences).
- BootstrapStore::new, inspect_format, begin_bootstrap, acquire_preparing, resume_bootstrap, publish_ready, validate_ready. BootstrapPlan::new creates the exact deterministic objects from the materialized initial root and full reserved range.
- SessionRepository::new(backend, identity, rank, max_records), inspect_sessions, acquire_sessions, load_sessions, open_session_record, mark_session_closing, mark_session_closed. Mutations take acquired authority and expected revision. NewSessionRecord.open_id is retained across uncertainty. Metadata is BTreeMap<Bytes, Bytes>.
- InoAllocator::new and reserve_range(reservation_id, count). Retain id across uncertainty/restart. A conflicting count under the same id is Corrupt.
- record::encode_record_bounded and encode_checkpoint_bounded reject Capacity before output allocation. Production append also validates supported record semantics. Unbounded encode helpers remain for fixture generation.
- The daemon still owns membership, blocklist proof, latest-map wait/barrier, union-of-writers fencing, joining rank lifecycle with shard receipts, bounded journal/input queues and all service/output gates. No live actions or daemon edits occurred in this lane.
