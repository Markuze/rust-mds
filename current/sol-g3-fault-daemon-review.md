## 3. Three cuts, actual commit tags and the terminal seal

### ReplyBeforeTransport

The ownership chain is implementable:

`validated wire input/context → completion in JournalRecord → Write → tagged Append → matching checked Committed → DaemonJournal::complete → journal_event → validated reply → PendingOutput → Session::transmit`.

`DaemonJournal::submit` still has the typed record before encoding (`journal.rs:124–140`). Runtime assigns the worker operation when it constructs the Command. Preserve the exact owner/operation/sequence and `operation_id(owner.gid, seq)`; the batch ID is not the runtime operation counter. `Server::on_storage_event` checks owner, pending operation and sequence before the callback (`server/runtime.rs:878–918`). Observe that checked receipt before `journal_event` can emit output; do not defer the commit callback or record-slot release for A.

`send_effects` currently removes a client/tid-only `pending_requests` entry before sending (`server.rs:1112–1166`). D5 must first provide the planned durable-key/attachment-bound context. Attach the observer identity/cause to the materialized output there. Keep the original op/tid and normal `check_invariants_for`; do not build a replacement reply or inspect later working inode state.

Suppress the selected logical SAFE reply at its actual funnel position, including regenerated duplicates. Release that queued item's byte charge once, but keep the logical suppression/context evidence within the 32-probe/one-arm bound. Do not hold a FIFO head or pause the session. Other-client rename/unlink and the selected client's cap revokes/renewals must still progress. The competing client's durable output uses its own input/probe/CommitRef. Sending neither the selected reply nor an ACK does not retire canonical E1 history or a D5 output obligation.

### FlushBeforeWorker

The only valid interception is `Runtime::flush_commands` before the selected Command's first successful `tx.try_send` (`server/runtime.rs:173–184`). Both `take_write` transfer sites (`:684–686` and `:851–853`) must enter that same gate. `take_write` setting `in_flight` is adapter ownership, not worker enqueue or native I/O (`journal.rs:80–83`).

Keep the original Command/body, pending operation and consumed record slot owned. Require q=d+1, worker_enqueued=false, append_started=false and store_confirmed=false. A held command must not keep `has_work`/daemon yield runnable. The existing quiescent-checkpoint condition must prevent publication of its speculative mutation. TERM, EOF, failure cleanup and NormalStop must never flush it.

Worker start belongs immediately before the first append-future poll, not before a completion wait. Current native append/reconciliation is `persistence.rs:526–542`. Once any append attempt starts, uncertainty remains uncertainty until checked reconciliation. Timeout, abort, dropped future, delayed response or a native post-write error cannot yield B1 evidence. Keep the exact logical ID/bytes for reconciliation, and classify StartedOutcomeUnknown rather than not submitted.

### FlushAckBeforeTransport and coverage

At Bound, install the B2 guard for exact `(SessionKey, rank=0, inode, T)`. Check the accepted ACK high-water cell before selected execution. At the final funnel seam, suppress every FLUSH_ACK for that key/rank/inode with tid ≥ T. Ignore cap_id, seq, mseq and dirty-mask equality in coverage matching. Another inode/key, FLUSHSNAP_ACK and ordinary non-covering CAPS/session/realm/reply output keep normal behavior.

Only T's own checked ClientFlush/CommitRef and its own ACK can create Hit. A later covering ACK can increase suppression counters but cannot substitute for the selected hit. B1 uses the specified acceptance-invalidates rule; do not silently broaden it into B2 suppression. Keep at most 128 key/inode high-water cells and separate exact/greater suppression counters.

Run ownership validation before this fault decision. Preserve accepted R1's Reclaim owner check and stale-discard semantics. The same `Session::transmit` handles immediate and deferred output, including terminal funnels. The hook must see raw/queued/regenerated covering ACKs there; output producers cannot bypass it with a direct link send.

After `ClientLink::send_raw` returns true, update actual accepted counters and the real counted `push_seq` exactly once, in that same turn. On false, retain ordinary fail-stop semantics. A deliberate fault suppression needs a distinct internal disposition from Sent, stale Discarded and Failed; it is neither a successful ClientLink call nor a transport error. Existing `Session::send == true` can already mean queued, so preserve the distinction through the callers and D5's handoff accounting. Never fake `send_raw=true` or advance push_seq for suppression.

`crates/msgr/src/conn.rs:193–209` confirms that true means acceptance into the messenger queue, not socket delivery or client processing. The observer must keep that exact proof level. Already accepted queue entries are not recalled or relabeled by the final freeze. Before ExitReady, selected_accepted/cover_accepted must prove that no selected/covering entry was ever accepted; independent peer evidence can still invalidate the trial.

### Why the final seal closes the output tail race

Hit/CutConfirmed alone cannot prove that a later queued invalidation did not occur. The v1 Sealing/CrashSealed edge does: serialize pending worker observations and ordinary output first, keep the guards installed, then freeze all final `Session::transmit` paths before generating ExitReady. Reserve its response capacity before changing the state. Capture the same final positions/counters into that final event. Do not read counters, yield, and freeze later.

After sealing, no worker handoff, journal callback, connection replacement, terminal funnel or raw-send path can produce an unobserved invalidating client send. A new failure is not a successful continuation; it follows the prescribed unsuccessful exit path. The controller still must fsync the final prefix, signal the exact pidfd before the deadline and verify actual SIGKILL status. Normal exit, early EOF, deadline, lost identity or an early peer/application outcome never becomes an expected crash. This source review makes none of those operational observations.

## 5. Bounds, nonblocking I/O and failure preflight

- One FaultState remains owned by the daemon turn. Async socket and worker tasks exchange bounded frames/facts only. Use async Unix I/O; filesystem setup or clock/credential reads must not introduce blocking work inside a reactor hook. Controller transcript/directory fsync runs on the controller's independent I/O path. The daemon verifies prefix receipts; it does not fsync evidence from `pump` or `transmit`.
- Enforce 8 incoming frames, 64 outgoing slots with 4 reserved response/failure slots, one cached response, one export, one arm/hit and one retained Append. Reserve critical response/event capacity **before** dependent actions: Bound before selected execution, WorkerEnqueued/AppendStarted before the corresponding handoff/poll, output acceptance capacity before the link call, and ExitReady capacity before sealing. Commit receipt processing must own enough observation capacity or fail synchronously without releasing output. Do not send first and discover that its event cannot be retained afterward.
- Preserve the original action/input under existing bounds while event capacity is unavailable. Do not wait synchronously for the controller. For ordinary observation overflow, latch failure before the next dependent action; no suffix-only restart or dropped event can qualify the trial. If even Failure cannot be emitted, exit unsuccessfully and let the required terminal-prefix rule reject the case.
- Stream the immutable image/cursor; never enqueue a full export. The declared maximum is 8 sessions + 32 histories + 16 inodes + 512 addresses + 128 ranges = **696 items**, plus Begin/End. Each Session references its complete set; each Address/WriterRange is one item. Validate counts/order/digest and keep Begin/End StatePoint identical. Aliases consume slots but do not duplicate canonical watches/high-water cells.
- Preserve all **64 full addresses total per union**, including type/family/IP/port/scope/nonce and original order. At most eight retained sets plus one pending replacement fit the fixed scope. Stream a pending union before dependent references become usable. Reject larger/ambiguous scope; never shorten it or replace an old referenced set. Scope failure must precede a dependent fence/output claim.
- The structural maximum-width budget is below 16 KiB: 12544 bytes for Hello/SnapshotRequest; 8192 for discovery/arm/bound/hit; 4096 for other shapes. This review checked the field/count argument, not encoded maximum-width examples. Later codec tests must prove the bounds including envelopes and strict integer/enum/union forms, duplicate-field rejection, depth ≤8 and length-before-allocation.
- Use checked ID/counter/deadline arithmetic and same-boot CLOCK_MONOTONIC nanoseconds. No wrapping IDs, fabricated timestamps or arbitrary free-form payload metadata. Cached identical response replay repeats the exact event ID/bytes without a new hash step. Keep only the named bounded milestone hashes and the cached response hash, even while asynchronous events follow a pinned milestone.
- Controller loss does not authorize flushing a held command, dropping dirty input as drained, completing a job, publishing a checkpoint or reviving a failed engine. `Runtime::cancel_pending` currently clears commands/inputs (`server/runtime.rs:123–133`), and `DaemonJournal::fail` clears its queued write (`journal.rs:98–103`). Reuse the planned terminal-preservation path before those destructive helpers. Generic early `?`/signal shutdown exits must not bypass it or the NormalStop handshake.

These are finite producer operations. No event expansion requires a blocking shared mutex, another engine owner or synchronous fsync. Failure is allowed instead of unbounded buffering, but it is not permission to lose protected input ownership or emit dependent client output after the failure.
