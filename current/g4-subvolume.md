# g4-subvolume
Task: Implement G4 subvolume tenancy. A subvolume is a tenant, not a shard.
Status: G4 gate closed 2026-11-16 (offline suites and live `g4_scenario` on fuse with target-g4). Daemon opens only `rmds.wal.0.0`.
Context: Setting `ceph.dir.subvolume` writes `SubvolumeId` and a snap realm on the directory's current shard. The same record sets `stable_subvolume_id` from 0 to that directory inode on every inode reached by primary links. It allocates no inode and writes no dentry. A nonzero id does not change. Clearing a directory that has any entry returns ENOTEMPTY. Clearing an empty directory clears the flag and leaves the published id in place. Inheritance and EXDEV follow a stored id only while that id still names a live subvolume root. Reply `subvolume_id` uses the stored id when it is nonzero. Quota pushes are `Effect::Quota` after commit. Auth caps are parsed from the MDS cap string and checked on the request path, including LOOKUPINO. Each shard actor has its own engine, step budget, and cache budget. A stopped or exhausted shard does not stop another. Cross-shard prepare, commit, and drop append to each participant's own stream. An incoming copy is invisible until commit. No commit on any participant discards it. One commit publishes the same inode number and one forward. A remote link whose directory is owned by another shard blocks a split. `wal_object(0)` is `rmds.wal.0.0`. A later shard would be `rmds.wal.<id>.0`. Startup does not create that object.
Next: G5 (`design/transactions.md`). Deferred: wire shard actors into `Server`, second WAL/stream, multi-rank (G6). Do not create `rmds.wal.1.0` until a gate assigns it.
